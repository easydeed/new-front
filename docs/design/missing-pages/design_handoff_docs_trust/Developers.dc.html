API reference · v1

Send the facts. A named person approves the deed.

Submit the facts of a California deed from your platform. The API returns a draft: an id, a status and a confirmation URL, not a stored PDF. A person you name opens that URL, sees the deed as it will print, and approves or sends it back.

02

Nothing reaches a stored instrument unseen.

This is why the API exists in this shape. DeedPro formats and records. It does not confirm facts. A one-call generate (POST, get a stored PDF, done) would let a machine produce a recordable instrument with no human in the loop, so that path does not exist.

The cost: you cannot treat generate as a synchronous one-call download. You hold the source data. If the human says the deed is wrong, you correct it in your system and POST again with a new Idempotency-Key. Replaying a rejected key returns the rejected draft. It does not mint a new one.

Named for the record, token for auth
Send approver.name and approver.role. Optional email is stored, never mailed in v1, and purged after the same contact-retention window as signer contact. You deliver the link.
Seven days
An unapproved draft expires. Preview bytes are dropped. The token then shows expired.
The bytes they approved are the bytes stored
The deed is rendered once at create. Approval promotes those preview bytes and stamps the hash. Re-rendering would store a different document than the one they saw.
Reject, do not edit
The confirmation page is not a second builder. The human sends a reason. You change the facts where they live.
03

Every request carries your key as a bearer token.

HeaderCopy
Authorization: Bearer dp_live_...
Test and live keys
dp_test_ and dp_live_. Both generate real PDFs on the same templates; test keys exist so you can build and demo without your traffic mixing into live records.
Shown once
Keys are stored hashed. The full value appears exactly once, when it is created. If it is lost, we issue a new one.
Rate limits
Per-key hourly and daily ceilings. Responses carry X-RateLimit-Limit and X-RateLimit-Remaining; exceeding one returns 429. Tell us your expected volume and we set the ceiling to match.
Revocation
A key can be deactivated at any time; calls with it stop immediately and return 403.

05

What the API will not do.

Worth reading before you integrate, and worth handing to your counsel.

It will not decide legal choices for you
Vesting, the transfer-tax basis, whether an exemption applies, which instrument fits the transaction: these arrive as facts you send, and they are recorded as your declarations. DeedPro formats and records; it does not choose. Nothing the API returns is legal advice, and no response asserts that a document is valid, effective, or ready to record.
It will not quietly ignore an input it cannot use
Send a vesting clause to a joint-tenancy deed and you get a 422 naming the conflict, not a 200 and a document that disregarded it. Required text must contain more than whitespace, numbers must be finite, and decimal amounts must fit the documented precision. Invalid input returns a field-specific 422 before a preview is rendered or stored. These checks do not verify identity, a property fact, or legal sufficiency.
Some instruments require a human flow by design
v1 covers the deed family only. Affidavits (of Death of Joint Tenant, of Trustee, of Spouse) and declarations (Homestead Declaration, Certification of Trust, TOD Revocation, Statutory POA) carry sworn statements, initial lines and checkbox elections. Their premise is a human hand at the moment of execution. They stay in the DeedPro app. This is a deliberate boundary, not a gap in the roadmap.
California only
Templates are measured to California county recorder requirements. property.state must be CA.
Recorded pages carry no verification chrome
Every API deed includes a blank California acknowledgment page for the notary to complete. The PDF does not print a QR code, verification URL, or DeedPro document ID; verification stays in the API response.
06

A retried request must not produce a second deed.

Send an Idempotency-Key header (your order or file number works well) and a repeat with the same key returns the original draft. If that draft was rejected or expired, you get that record back. A replay does not resurrect a rejected body as a new draft.

HeaderCopy
Idempotency-Key: order-48219

Keys are scoped to your API key. PDF rendering happens server-side, so allow a generous timeout (60s) and retry with the same idempotency key, not a fresh one.

08

Anyone holding a document ID can check it. It reveals nothing else.

GET /verify/{document_id} needs no API key. A valid response contains only the document ID, deed type, status and creation time. It does not publish the property address, APN, or party names.

Public verification is limited to 60 attempts per client address per hour. A 429 response includes Retry-After and rate-limit headers.

09

A calculator for your declaration, not a decision.

POST /transfer-tax/calculate returns a county and city breakdown for a value and location. The amount that prints on the deed is the one you send in transfer_tax.

County
One rate statewide: $0.55 per $500 increment or fraction of the supplied taxable base (R&T §11911).
City
City rates apply only to cities that levy their own documentary transfer tax. A city that levies none is reported as levying none; no generic rate is applied.
Approximations
City rates approximate tiered municipal schedules. Verify against the current schedule for the recording jurisdiction; the response carries this caveat alongside the number.
transfer_tax.basis
The basis you direct the deed to print: full_value or less_liens. DeedPro does not infer or verify that legal choice.
transfer_tax.exempt_code
A free-form string. The API does not maintain or validate against a statutory exemption-code list. Send a code only after your professional has determined the applicable wording.
10

Versioning and changelog.

The current version is v1, covering the deed family. Additive changes (new deed types, new optional fields, new response keys) ship within v1 without notice. Apart from the safety cutovers recorded below, a breaking change would ship under a new path, /api/v2.

2026-11-10
County calculator rounding repair
The county estimate now uses $500 increments or fractions instead of a continuous percentage. Municipal rate logic is unchanged. Calculation does not determine taxability or select an exemption; confirm the applicable jurisdiction and instructions separately.
2026-11-10
v1 interspousal safety hold
New interspousal-transfer creation and pending approval are suspended while its tax instructions and legal form await domain review. Seven API deed types remain available. Stored completed PDFs remain accessible; this hold does not rewrite existing documents or choose an exemption for you.
2026-11-09
v1 tax-deed safety hold
New tax-deed creation and pending approval are suspended while the county workflow and form are reviewed. Existing stored PDFs remain readable. This is an explicit change to v1 availability; no substitute instrument is selected for you.
2026-11-09
v1 input safety cutover
Validation revision P02-2026-11-09 deliberately tightens v1: blank required text, nonfinite numbers and malformed or oversized inputs previously accepted now return 422. Existing integrations must review the published schema before cutover. Routes and response shapes stay unchanged; no tax basis, exemption or other legal choice is made for the caller.
2026-08-27
v1 Model 2 cutover
POST /api/v1/deeds returns a draft and a confirmation URL. A stored PDF exists only after approval. approver.name and approver.role are required. Reject-with-reason; a replayed Idempotency-Key does not resurrect a rejected draft.
