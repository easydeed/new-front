DeedPro API

Generate recorder-formatted California deeds from your platform. You send the facts of the transaction; a named officer confirms the rendered instrument; the API returns a stored, hash-stamped PDF on the same templates and page geometry the DeedPro app renders.

Read this before the quickstart

Three things that will change how you scope this

Most integrators arrive assuming this is JSON in, PDF out. It is not, and the difference is the reason to use it. Worth reading now, and worth handing to your counsel.

A PDF requires a named human

Creation returns a draft, not a document. urls.pdf appears only after a confirm call carrying a reviewer's name. Plan a review surface in your product.

The confirmation step →
The instrument decides the vesting

Two deed types state vesting on their own face. Send grantee.vesting to one and you get a 422 naming the conflict — never a 200 that ignored you.

Instrument doctrine →
v1 is the deed family only

Affidavits, homestead declarations and statutory POAs carry execution-act machinery a machine call has no hand for. They stay in the app. Deliberate boundary, not a roadmap gap.

Coverage & limits →

DeedPro formats and records; it does not choose. Vesting, transfer-tax basis, whether an exemption applies, which instrument fits the transaction — these arrive as facts you send and are recorded as your declarations. Nothing the API returns is legal advice, and no response asserts a document is valid, effective, or ready to record.

  -H "Authorization: Bearer dp_test_YOUR_KEY" \
  -H "Idempotency-Key: order-48219" \
  -d '{ "deed_type": "grant_deed", "property": ..., "grantor": ... }'
