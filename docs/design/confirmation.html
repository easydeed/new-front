The confirmation step

The PDF does not exist until someone has put their name on it

This is not a review queue bolted onto a renderer. It is the state machine. There is no request you can make, no flag you can set, and no plan you can buy that produces a recordable California deed without a named person confirming the rendered instrument first.

awaiting_confirmation
A draft that renders

Your POST returns a deed id and a review URL. The draft is laid out on the real template at real page geometry — margins, statutory furniture, the blank acknowledgment page — so the reviewer reads the document, not a summary of the JSON you sent.

A person, by name

The confirm call requires a reviewer identity and the hash of the draft they actually looked at. Confirm a draft that has since changed and it fails. Confirm as a service account and it fails.

A document, and a record of who

The PDF is written once, hash-stamped, and stored insert-or-refuse: a differing hash for the same document is rejected rather than overwriting what is there. The confirmation record is retrievable for as long as you keep the file.

There is no fourth path. A draft that is never confirmed expires and costs you nothing.

The confirm call

Two required identity fields and the hash of the draft as rendered. The hash is what makes the record mean something: it binds the name to the exact bytes, not to a deed id whose contents could have moved.
